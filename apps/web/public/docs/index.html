START BUILDING

Your first request

Create a connection and a server key in Control Center → API. Store the key as GSW_API_KEY in your application server’s secret settings.

A successful GET /connection returns the bound sender, connection mode, access and daily submission limit. Use the returned sender.id when submitting email.

CUSTOMER SETUP

Connect an external web app

  1. Set up your GSW workspace.

    Sign in at GSW Mail. A workspace owner or administrator manages API access for the customer application.

  2. Prepare the sending mailbox.

    Add and verify your domain, provision an active mailbox and finish its mailbox authorization. Live sending requires verified SPF, DKIM and DMARC. Admin sign-in alone does not authorize mailbox access.

  3. Create the connection.

    Open Control Center → API, give the connection your application’s name and choose its mailbox. New connections are live and bind to one mailbox.

  4. Create and save a server key.

    The portal shows the secret once. Store it on your server; never put it in browser JavaScript, mobile bundles, URLs or a public repository. The current portal issues 30-day keys.

  5. Integrate and verify.

    Call /connection, discover /capabilities, then exercise read operations and a controlled idempotent write. Add a signed webhook endpoint if your application needs asynchronous email or operation events.

The current onboarding flow uses an existing GSW workspace and mailbox. It does not provide a separate API subscription checkout, automatic customer billing or a public API plan purchase flow.

Authentication

Every private endpoint requires the same header. Access covers available functions for the bound mailbox; there are no per-operation scope selections or recipient allowlists.

Authorization: Bearer YOUR_SERVER_KEY
Opening /capabilities in your browser’s address bar does not send this header. Being signed in to the admin portal is a separate authentication flow. Use a server request with the key.

Keys cannot manage workspaces, domains/DNS, mailbox provisioning, billing, account credentials or API keys. Those controls stay in the administrator portal.

Connection & discovery

GET/connection

Inspect the key’s mailbox binding, connection state, sender ID and daily direct-email limit.

GET/capabilities

Discover the available mailbox operations, JSON input schemas and whether each operation changes data. Requires your bearer key.

The public operation reference contains static schemas only. It exposes no mailbox records and does not authorize execution.

Mailbox operations

Use a single endpoint for the available mailbox functions. The catalog below is generated from the same operation registry used by the API. It reflects current coverage; a product UI feature may not yet have a registry operation.

POST/operations
{"name":"mail.list_recent","arguments":{"limit":10}}

Reads return the existing mailbox service result. For any operation marked Changes data, include an Idempotency-Key. Do not provide account, user or workspace context overrides: the server derives them from the connection.

Send & track email

POST/emails

Persist an email submission for asynchronous processing. Requires an Idempotency-Key.

curl https://mail.guidedstepswellness.com/integrations/v1/emails \
  -H "Authorization: Bearer $GSW_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: inquiry-123-ack-v1" \
  -d '{"senderId":"MAILBOX_UUID","to":["visitor@example.org"],"subject":"Thank you","text":"We received your inquiry."}'

Replace MAILBOX_UUID with sender.id from /connection. Supported fields: required senderId, to, subject and text; optional html, replyTo and string-valued metadata.

FieldLimit
to1–10 addresses
subject1–998 characters, no control characters
text / html100,000 characters each; request body 256 KiB
metadataUp to 10 entries; keys 64 and values 256 characters

202 means the submission was persisted and accepted for processing. It does not prove inbox delivery; poll status or subscribe to signed delivery webhooks.

GET/emails/{id}

Poll the returned ID to inspect processing status. Status records are isolated to the connection that created them.

AI chat, including Kimi

POST/ai/chat
{"messages":[{"role":"user","content":"Draft a warm welcome message."}]}

Uses the connected mailbox’s enabled AI settings and selected provider, including Kimi. The API service must have KIMI_API_KEY configured. The response contains content and model; provider reasoning is not returned.

This endpoint generates text. Use mailbox operations for explicit actions such as sending or scheduling.

Send 1–50 user/assistant messages, each up to 50,000 characters, within the 256 KiB request body limit.

Signed customer webhooks

Add an HTTPS endpoint from Control Center → API to receive asynchronous events without polling. The signing secret is shown once and must stay on your server.

POSTyour HTTPS endpoint

GSW Mail delivers supported events with a stable event ID and HMAC signature. Failed deliveries retry automatically.

Current event types: email.accepted, email.delivered, email.deferred, email.bounced, email.complained, and operation.completed.

X-GSW-Webhook-Id: EVENT_UUID
X-GSW-Webhook-Timestamp: 1793505600
X-GSW-Webhook-Signature: v1=<hex hmac-sha256>

Verify the signature against the exact raw request body using HMAC-SHA256 over timestamp + "." + rawBody. Deduplicate by X-GSW-Webhook-Id; retries reuse the same ID. Return any 2xx status only after your application has durably accepted the event.

Webhook targets must use public HTTPS. GSW Mail rejects localhost/private-network targets and does not follow redirects.

Production verification

New API connections are live. Verify them with low-risk, controlled requests rather than a separate simulation mode.

  1. Verify /connection reports the expected mailbox and connection.
  2. Retrieve /capabilities and confirm the operation schemas your application will use.
  3. Run a mailbox read and verify the expected account boundary.
  4. For writes, use an Idempotency-Key, retry the identical request once and confirm it does not execute twice.
  5. For sending, use a controlled recipient and verify processing plus delivery evidence through status or a signed webhook.

Control Center → API shows service health, daily/total usage, key expiry health, webhook state and recent activity. If mailbox authorization needs renewal, use the mailbox recovery action rather than creating another connection.

Errors, limits & safe retries

{"error":{"code":"invalid_api_key","requestId":"req-123","retryable":false}}
StatusWhat to do
400Check JSON, input schema and required Idempotency-Key.
401Supply a valid, unexpired and unrevoked bearer key.
403Check connection state, mailbox readiness, AI settings and operation eligibility.
409The same idempotency key was used with different arguments. Reconcile the original action.
429Respect Retry-After. Direct-email daily limits and sender rate limits apply.
5xxUse retryable and requestId for diagnosis. Reuse the same write key and payload.

Idempotency keys are 1–200 characters using letters, numbers, periods, underscores, colons or hyphens. Direct-email retries return the original submission. Operation write retries return execution status and a resource reference, not the full original result. An in-progress or unknown result requires investigation before another write.

The default direct-email limit is 100 submissions per connection per UTC day; inspect /connection for its configured value. Mailbox operations have their own service validations and sending limits.

Manage access over time

Rotate keys before expiry: create a replacement, update your application’s secret, verify a request and revoke the previous key. Control Center surfaces keys expiring within seven days. Pause a connection to defer new work, or remove the connection to revoke its active keys and cancel pending webhook delivery while retaining audit history.

Already accepted external actions cannot be recalled. Schedules and automations created through a connection have their own lifecycle; pause or delete them separately when retiring a workflow. If mailbox authorization expires or is revoked, sign in as the mailbox owner and use Restore mailbox service access. Older authorizations created before encrypted credential storage require this one-time renewal; token hashes cannot be recovered as credentials.
